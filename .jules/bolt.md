## 2025-03-02 - Cache-aside pattern for Supabase REST memory storage with mutation triggers
**Learning:** In highly autonomous systems where agents frequently read and write to a central memory state, query endpoints like `GetMemory()` can generate significant REST/database overhead, especially on dashboard polls. Implementing an in-memory 30-second TTL cache drastically improves load speed and cuts database read traffic. To guarantee consistency without introducing race conditions or stale metrics, mutations (via `MemoryAI` or `saveMemory`) must immediately invalidate the cache state synchronously.
**Action:** Always wrap frequently polled read-heavy REST query functions in short TTL in-memory caches, and hook invalidate callbacks directly into all mutation methods of related entities.
